# Retained Input Node Evidence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect actual synthetic browser input targets to exact existing trace candidates through bounded, versioned node evidence while keeping all results diagnostic.

**Architecture:** Extend the existing observer with an opt-in version-two contract and strong references to actual window-capture targets. Use the collector's owned page CDP session to validate the root context, map retained nodes to backend IDs, and monitor lifecycle continuously. Pass the existing fifth `analyzeTrace` evidence envelope through closed version dispatch and the current confined sidecar reader.

**Tech Stack:** Node.js 22, Playwright CDP session, existing Node test runner and trace analyzer; no dependencies.

**Spec:** `docs/superpowers/specs/2026-10-18-retained-input-node-evidence-design.md`.

## Global Constraints

- Preserve version-one observer declarations, sidecars, interpretation, limits, and original collector hash `96a969d576f7610b66217294480c444a36205cec69dba66e8dee0b9a820ce8ae`.
- Retain targets only for `--run --browser=installed-brave --observe-inputs --retain-input-nodes`; reject this flag in every other invocation before resources start.
- Keep the Event Timing threshold at 16 ms, maximum 512 records, maximum 240 KiB record bytes, and maximum 256 KiB sidecar bytes. Reserve the version-two envelope budget before accepting records; never truncate contenders or raise these limits.
- Retain at most 32 actual Nodes and serialize at most 16 KiB of mappings. Backend IDs are positive signed-32-bit integers; never serialize remote object handles or DOM content.
- Apply retention only to the owned synthetic fixture. Do not add page delays, app changes, or repeated trials to force an API entry; preserve failures and report unavailable evidence.
- Keep the Brave .80 compatibility profile, distinct bundle/runtime revisions, executable hash, headful launch, and `chromiumSourceIdentity: unverified`; formal status and percentiles stay unavailable.
- Leave API target nullness unchanged. Labels select existing actions only; neither labels, ancestors, locators, selectors, nor `composedPath()` establish identity.

## Review Focus

- A synchronously removed target still maps from the actual window-capture target; a null API target stays null. Pin this in Task 1.
- A registered ancestor, shadow-retargeted target, or pointer-capture ambiguity cannot manufacture a supported node identity. Pin this in Task 1.
- Invalidation during any asynchronous mapping or cleanup boundary prevents later mapping commands and success. Pin this in Task 2.
- Duplicate or malformed API/legacy contenders remain ambiguous before filtering, and frame/PID/context mismatches reject association. Pin this in Task 3.
- Oversized, substituted, linked, or old-version sidecars cannot bypass byte/hash/confinement checks or acquire version-two meaning. Pin this in Task 3.
