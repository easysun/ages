# Same-Document Retained Node Evidence, Version Three

## Purpose and boundary

Answer one diagnostic question: during one synthetic route-open, does retained-node identity remain stable while the collector receives one root `Page.frameStartedLoading` and then one root `Page.navigatedWithinDocument` with `navigationType: historyApi`? This is callback-receipt order only; it establishes no source-event time, causality, general Chromium behavior, phone/human-input result, protocol-wide validity, source attestation, or formal qualification.

Version three is explicit opt-in and diagnostic-only. Preserve v1/v2 declarations, sidecars, accepted fingerprints, behavior, and analyzer output. Add no action segments, formal samples, qualification, or retrospective reinterpretation. Reuse the fixture and primary-open action; add no actions, delays, retries, idle windows, or source changes.

Events have exactly `sequence`, `phase`, `source`, `method` and applicable flat catalog fields; sequence is listener receipt order, not source time. Phases are `baseline`, `before-input`, `primary-action`, `route-ready`, `post-trace-analysis`, or `cleanup`; source is `page` or `browser`. First invalidation is null or `{sequence, phase, method, reasonCode}`. Cleanup has the four existing listener/reference/object-group booleans. Reject unknown keys and store no URLs, titles, DOM descriptions, page text, headers, cookies, expressions, payloads, timestamps, or stacks. IDs are bounded opaque values; execution-context IDs are positive bounded integers; reasons and enums are closed.

The pinned catalog covers Page lifecycle, Runtime context create/destroy/clear, Inspector detach/crash, and Target info-change/destroy/crash/attach/detach on both owned sessions. Flat fields are limited to `frameId`, `parentFrameId`, `loaderId`, `executionContextId`, `contextUniqueId`, `isDefault`, `targetId`, `sessionId`, `navigationType`, and `detachReason`. Unknown, malformed, out-of-scope, unclassifiable events, transport/trace loss, and catalog mismatch invalidate. Allow exactly 128 entries only with zero drops; overflow invalidates and preserves the first invalidation.

The only allowed receipt pair is one root-frame `Page.frameStartedLoading` callback received after acknowledgement for the existing `pilot-100-interactive-open:segment-start` `TimeStamp` marker and tracker phase update to `primary-action`, then one root-frame `Page.navigatedWithinDocument` callback with `navigationType: "historyApi"` received later. Do not add clocks, timestamps, or correlation joins. If source-time ordering is required, return unavailable/unsupported. The loading event carries only a frame ID; do not synthesize a loader ID or infer a cause from it. Reject missing, duplicate, foreign-frame, malformed, wrong-phase, reordered, fragment, cross-document, child-frame, repeated, or unknown navigation. ## Identity and lifecycle proof

Before arming, install pinned CDP subscriptions and snapshot root frame/loader, selected target/session, and default unique context. Select v3 explicitly with `retainedNodeEvidenceVersion: 3` in `installTrustedStimulusObserver(page, options)` and `createRetainedInputNodeEvidenceTracker(options)`; default retained-node version 2 output is unchanged. Tracing starts after arm; stream bytes arrive only after `Tracing.end`. Establish renderer PID offline from `TracingStartedInBrowser` and verify root-frame/PID association precedes the marker and selected candidate in trace order. Do not claim a live PID baseline before click.

The browser observer owns source capture and strong references. At window capture, retain literal trusted `event.target` under its opaque token and record `targetIsNode`, `ownerDocumentMatches` (`ownerDocument === savedDocument`), `rootContainsTarget` (`savedRoot.contains(event.target)`), `connected` (`isConnected === true`), and `composedPathStartsAtTarget` before bubbling. `retainedTargetProof` is null without one unique trusted `kind: "dom"`, `type: "click"`, `phase: "primary"`, `isTrusted: true` record. Otherwise it has exactly `sourceRecordIndex`, `documentId`, `targetToken`, `mappingIndex`, `sourceCapture`, `baselineScope`, and `finalProof`. The zero-based index must point to that record; document and token must match. `sourceCapture` has exactly the five booleans above. If token is null, mapping index and final proof must also be null. Token, mapping index (0–31), baseline scope, and final proof may be null only when unavailable; null never qualifies. Complete proof requires each to be present, source booleans true, and the index consistent.

After route-ready, the tracker maps the same token in the same unique context. `mappingIndex` indexes `retainedNodeEvidence.mappings`, whose token and positive backend ID must match. `baselineScope` is null or `{frameId, loaderId, contextUniqueId, targetId, sessionId}` captured before arm. After trace completion, offline-check raw trace ordering; while CDP listeners remain active and before release, the observer compares saved document/root/target and the tracker re-describes that object. `finalProof` is null or exactly `{stage, savedDocumentSame, savedRootSame, savedTargetSame, targetOwnerDocumentMatches, rootContainsTarget, connected, mappedBackendNodeId, finalBackendNodeId, cdpScope}`. `stage` is `post-trace-before-release`; `cdpScope` has the same five keys as baseline. `savedDocumentSame` means `document === savedDocument`; `savedRootSame` means `document.documentElement === savedRoot`; `savedTargetSame` means the retained map returns the saved click Node; `targetOwnerDocumentMatches` means its owner document remains `savedDocument`. Backend IDs are integers from 1 through 2,147,483,647 and both must equal the mapping. Require true source, saved-reference, and owner-document booleans and equal baseline/final scope. Final `rootContainsTarget` and `connected` may be false after detachment; preserve those booleans and do not fail solely for detachment. Unavailable proof steps are null; null never qualifies. The single per-case object is bounded by record index 0–511 and mapping index 0–31 and shares the 16 KiB mapping and 256 KiB sidecar budgets; reserve worst-case bytes. A complete witness requires full proof and analyzer consistency checks; generic status is insufficient.

Earlier route-ready mapping is provisional. Success requires the receipt pair, complete source and final target proof, unchanged document/frame/loader/context/target/session identities at the final proof point, and the raw trace PID epoch through trace end. After cleanup, freeze the sidecar, write the manifest, then write the run cleanup receipt with the manifest's actual SHA-256. Only after that may the authoritative CLI analyze the immutable files; any cleanup failure is unavailable.

Final `connected` and `rootContainsTarget` are recorded but may be false after detachment. A generic `status: "complete"` is not proof. Preserve all API and raw legacy contenders before filtering.
