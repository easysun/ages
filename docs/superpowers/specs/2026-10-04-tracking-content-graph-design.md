# Ages-Native Tracking and Content Graph Design

**Status:** Approved by the user on October 5, 2026. The user subsequently authorized all remaining designs and plans to proceed without further human approval. Implementation retains tests, independent review, and release verification gates.

## Goal and boundaries

Build Ages-native short-link analytics and relationships between durable content. Each Ages user configures their own tracking integrations; the product does not connect to a lihi.io account. The first release includes first-party click totals and source breakdowns, UTM/custom parameters, optional GA4/Meta Pixel/GTM browser tags, and a manually authored content graph. It does not estimate unique visitors.

Keep `Asset`, `TimelineItem`, `Timeline`, `Link`, and graph identity separate. `Link` remains a distribution handle with a slug, target, and expiry/deactivation policy. Expiring or disabling a Link must not delete its target or any graph node or edge. A graph edge is a creator’s assertion, not an endorsement by its target owner; do not create reciprocal edges automatically.

## Approaches considered

| Area | Option | Trade-off |
| --- | --- | --- |
| Browser tags | Keep the existing direct 302 and add first-party counts/UTMs | Simple and safe, but the browser never runs GA4, Pixel, or GTM. It does not meet the agreed scope. |
| Browser tags | Run customer tags on the Ages application origin | Fewer hosts, but a user-configured GTM container shares an origin with authenticated product state. Reject. |
| Browser tags | Dedicated tracking origin with a consent interstitial | Adds a redirect and a host to operate, while isolating customer tags from the app. **Recommend.** |
| Content identity | Treat each short Link as a graph node | Link expiry and slug changes would destroy durable references. Reject. |
| Content identity | Stable `ContentNode` and typed `ContentEdge`, separate from Links | Preserves durable identity and supports backlinks without a social feed. **Recommend.** |
| URL identity | Globally canonicalize and merge identical URLs | Risks merging references with different owners, context, or visibility. Defer; external references are owner-scoped in v1. |

## Tracking contract

### First-party aggregates

- Enable native aggregate analytics by default for every Link, including accounts without external provider IDs. Show click totals and source breakdowns in the owner interface.
- Count each valid `GET /s/:slug` resolution once; do not count `HEAD` or failed/inactive/expired/moderation-blocked resolutions. Bot and preview `GET`s may still count, so label the metric **clicks**, not people or unique visits.
- Store daily aggregates using `Asia/Taipei`. Store no raw IP address, user agent, full referrer URL, or event-level visitor record.
- Report two independent source dimensions: an owner-created sharing-channel label and a normalized referrer hostname. A channel label is self-reported attribution, not verified attribution: recipients can edit the URL. Accept only configured labels; invalid or unknown labels go to `Other`. Missing referrer is `Direct/unknown`.
- Normalize a referrer to a lowercase IDNA hostname with a trailing dot and port removed. Accept only HTTP(S) referrers; reject IP literals, localhost, and local-only hostnames. Discard path, query, and fragment. Cap each Link at 20 configured channel labels and each Link/day at 20 distinct referrer host buckets plus `Other`.
- Use daily counter rows/buckets, not click-event rows. This bounds writes and source cardinality for a day; lifetime history still grows by Link × day. Do not silently expire aggregate history. Choose and document a retention/deletion policy before adding automated cleanup.
- Analytics ownership follows the Link owner. Deactivation does not silently erase history. Any permanent Link deletion behavior must define the corresponding aggregate deletion behavior.

### Parameters and destination URLs

- Support the five conventional UTM fields: `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, and `utm_content`. Support at most 10 custom scalar query parameters per Link; keys are at most 40 characters and values at most 100 characters. Reject reserved keys, keys beginning `utm_`, control characters, and duplicate keys. Values are literal strings in v1: no macros, template evaluation, or executable content.
- Apply URL encoding through the platform URL API. Preserve unrelated destination query parameters; configured values replace existing values with the same key. Do not append tracking parameters to Ages Timeline or Asset URLs. Those targets may emit only the fixed Ages click event to an explicitly enabled provider after consent.
- Never include a destination URL, Timeline title/caption, media metadata, or private content in vendor event payloads.
- Direct GA4 custom fields use safe stable scalar names: `ages_c_<key>` for ASCII alphanumeric/underscore keys up to33 characters, otherwise `ages_h_<first32 SHA256 hexadecimal characters>` of the exact key. Preserve existing hashes for well-formed keys; accepted malformed UTF-16 keys use an exact code-unit byte representation disjoint from valid UTF-8 before hashing, so replacement-character conversion cannot merge distinct keys. Values remain literal and bounded; Link settings show the mapping needed for GA custom dimensions. Original bounded key/value structures remain available for GTM and Meta. Owner keys never become SDK routing/configuration options.

### Optional GA4, Meta Pixel, and GTM

- Store provider IDs per Ages account: one GA4 Measurement ID (`G-…`), one numeric Meta Pixel ID, and one GTM container ID (`GTM-…`). Enabled account settings apply to existing and newly created Links by default; each Link can disable optional providers. An enabled GTM container also works without an Ages-configured GA4 or Meta ID. V1 does not override provider IDs per Link. IDs are public identifiers, not credentials. V1 accepts IDs only; no custom JavaScript, custom HTML, or arbitrary tag URL fields.
- Use a dedicated tracking origin on a separate registrable domain, with separate TLS, cookies, storage, and origin. The application origin never loads these tags. Do not share app sessions, cookies, CORS access, API capabilities, or authenticated page content with the tracking origin.
- Links with no enabled optional provider keep their existing direct redirect or Asset delivery, adding only the first-party aggregate and configured external-URL parameters. A valid short-link GET with optional providers records the first-party aggregate once and redirects to an opaque, short-lived, single-use ticket on the tracking origin. Ticket page and final redirect requests must not increment it again. Every app-to-tracking redirect sends `Referrer-Policy: no-referrer` so the consent document cannot expose the incoming app URL through `document.referrer`. That page lists enabled providers and starts with optional tracking denied. The visitor can allow the displayed providers or continue without tracking. Denied consent, skip, and timeout before loading tags must continue without vendor calls. A provider failure after loading may already have made requests, but must not block continuation. First-party aggregation is independent of this choice.
- After consent, emit one fixed `ages_link_click` event with only the opaque link identifier, target kind, configured channel, and bounded UTM/custom scalar values. GTM is isolated to the tracking origin; its owner-managed container may run that owner’s tags, but receives no app secrets or destination URL. V1 limits GTM network/script destinations to approved Google/Meta origins through CSP; containers requiring other suppliers are unsupported. Provide explicit direct-versus-GTM event routing per provider; avoid enabling both dispatch paths by default. Before the click event, provide the container a separate fixed `ages_provider_eligibility` dataLayer event with boolean `ages_ga4_eligible` and `ages_meta_pixel_eligible` fields, each true only for an enabled provider routed through GTM, so its documented trigger conditions honor individual Link opt-outs and avoid duplication with direct delivery. Owner custom keys must never become this configuration signal. Ages-configured GA4/Meta tags must trigger on `ages_link_click` only when their corresponding Data Layer Variable equals true. A standalone GTM container still receives `ages_link_click` when no Ages provider IDs are configured; its container-owned setup remains the owner’s responsibility. Owners remain responsible for configuring their published container to use those conditions; observed production events must verify that behavior.
- Complete the redirect through a server-validated ticket endpoint. Recheck Link active/expiry/moderation state and current target visibility/grant before resolving. Tickets cannot be used to read Ages APIs or bypass target authorization. External URL continuation uses an app-origin no-store, vendor-free meta-refresh/fallback-anchor document after validation so strict tracking form-action restrictions do not block the browser's external navigation; no JavaScript or additional credential is required. Use a restrictive CSP, no third-party tags before consent, and no app-origin CORS grants. The consent document uses `Referrer-Policy: strict-origin` so ordinary cross-origin POST forms retain the exact tracking Origin; no-referrer would make it null. Bootstrap-owned vendor scripts explicitly request no-referrer; vendor-managed requests may disclose only the fixed tracking origin, never a ticket path/query or app URL. The app continuation document uses `Referrer-Policy: no-referrer` before external navigation. Verify actual Origin and referrer behavior with and without JavaScript. See [browser referrer-policy behavior](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy).
- GA4 setup requires the owner to disable Enhanced Measurement in the selected web data stream; `send_page_view: false` only suppresses the configuration command's default pageview and does not disable enhanced events. Ages uses documented manual dispatch and sanitized page metadata; local SDK stubs verify Ages code, while the absence of unintended pageview, form, and enhanced-measurement dispatch remains a provider production gate. Provider-generated session events are not additional explicit Ages click dispatches. See [Google pageview documentation](https://developers.google.com/analytics/devguides/collection/ga4/views) and [Enhanced Measurement settings](https://support.google.com/analytics/answer/9216061).
- Before production, provision and verify the separate DNS/TLS domain and test provider IDs. Local development can use two distinct loopback hostnames and synthetic IDs; it must not require production DNS or vendor accounts to test first-party counts, consent/skip, expiry, ticket replay, and redirect authorization.

## Content graph contract

### Identity and supported nodes

- Add stable `ContentNode` identity independent of `Link`: node ID, owner, kind, visibility, timestamps, and a reference to its underlying content. A Timeline node references a Timeline ID; an external-reference node stores an owner-entered validated HTTP(S) URL and optional title; an Asset node, when enabled, references an Asset ID. Do not globally deduplicate external URLs in v1.
- The initial graph slice supports Timeline and external-reference nodes. External URLs render as escaped text and ordinary links; do not fetch remote pages or embed remote media. Asset graph nodes are deferred until there is an explicit, durable graph-sharing grant. Existing Assets remain private and current expiring Link grants do not make an Asset public. If Asset graph support is later added, recheck the owner’s durable grant on every render/stream and never use an edge to broaden access.
- Node visibility is `private`, `unlisted`, or `public`. Effective access requires both the node policy and the underlying content policy to permit the viewer. For Timeline nodes, effective visibility is the more restrictive of the two (`private` before `unlisted` before `public`); a public node referencing an unlisted Timeline is effectively unlisted, and a private Timeline remains owner-only. A missing or moderation-blocked Timeline, cover, or story member makes its node unavailable under the existing Timeline availability rules. Evaluate edge activation, acceptance, backlinks and indexing using this effective visibility, not the node field alone. Public means indexable under existing public-content rules; unlisted is URL-accessible and noindex; private is owner-only. A node or edge cannot grant access to its underlying content.

### Directed edges and backlinks

- Store a stable `ContentEdge` with source node, target node, one allow-listed type (`related_to`, `references`, or `continuation`), creator account ID, creation time, and approval/moderation state. Require the authenticated creator to own the source node. A foreign node cannot be used as a source without a future explicit collaboration feature.
- Render an active edge as a backlink on its target, attributed to the creator/source owner using only a safe public Ages label; never reveal auth email or identity-provider details. If no public label exists, use a non-identifying “added by source owner” attribution. The target owner may suppress, block, or report an incoming edge. These controls do not create a reverse edge.
- When both endpoints are public, a source owner’s cross-user edge becomes visible immediately on the target. This is the approved public-content rule; it represents the creator’s assertion, not target-owner endorsement.
- If either endpoint is unlisted, require target-owner acceptance before activating a cross-user edge. Render it only in a context where the viewer already has access to both endpoints; never expose an unlisted node through a public backlink list, directory, or index. Private endpoints are never exposed cross-user; same-owner private edges, if supported, remain owner-only.
- Recheck each endpoint’s visibility, ownership, moderation state, and required grant at read time. A change to private, removal, blocking, or grant revocation hides the edge/backlink promptly. Removing or expiring a Link does not remove a node or edge.
- Tags/hashtags remain owner-scoped classifications, not public topic pages. Link tags use the existing tag conventions: up to 20 distinct nonblank strings per Link, each 1–64 UTF-16 code units, rejecting exactly C0 controls (U+0000–U+001F) and DEL (U+007F) as the existing Asset tag validator does; do not silently narrow its accepted character set. Preserve Unicode, case, and intentional spaces, including Chinese labels such as `旅行`; use exact-match filters and no trending/global discovery. A hashtag presentation does not normalize or rewrite the stored tag. Link tags do not implicitly become graph edges or Asset tags.

## Delivery slices

1. Add Link tags, first-party daily click totals, channel/referrer breakdowns, parameter validation, and an owner report in `Asia/Taipei`. Agree deletion/retention behavior before any automated aggregate cleanup.
2. Add account-level provider IDs and the isolated ticket/interstitial/consent flow. Keep provider events fixed and bounded; no arbitrary code injection.
3. Add stable ContentNode identity for Timelines and owner-managed external references, with explicit visibility and safe rendering.
4. Add typed directed edges, target backlinks, public immediate visibility, unlisted acceptance, and owner suppression/block/report controls. Defer Asset graph sharing until its durable grant is designed.

AI-suggested edges, a social feed, comments, follows, global URL deduplication, remote embeds, and public hashtag discovery are out of scope until the manual graph and existing upload-to-Timeline loop are proven.

## Acceptance checks

- Valid GET increments once; HEAD and failed resolutions do not. Daily bucketing uses `Asia/Taipei`; aggregate source cardinality is capped; arbitrary hosts/labels cannot create unbounded buckets; storage contains no raw IP, user agent, or referrer URL. Retention is explicit and no background job silently expires aggregates.
- Parameter limits, reserved-key rules, encoding, destination-query replacement, invalid URLs, and owner isolation are tested. Every accepted literal parameter combination, including JSON-escaped quotes, backslashes, and accepted surrogate code units, must fit a derived finite ticket-storage bound and continue successfully without truncation; already-applied migrations remain forward-only.
- Consent-denied, skip, and pre-load timeout flows reach the same authorized destination without vendor calls. Provider-load failure does not block the final authorization-checked redirect. Consent-enabled events have the fixed schema and omit destination/content data. Ticket replay, expiry, Link deactivation, target privacy changes, and grant revocation fail closed.
- Tests prove the tracking origin cannot read app cookies/APIs, and app pages never load owner tags.
- A public cross-owner edge appears as an attributed target backlink immediately; it creates no reciprocal edge. Unlisted edges require target-owner acceptance and do not leak through public backlinks. Private nodes cannot be exposed. A public node referencing an unlisted Timeline remains effectively unlisted; a private or unavailable underlying Timeline cannot be exposed by node rendering or backlinks. Suppression/blocking hides the backlink. Invalid edge types and foreign-source writes fail.
- A Link’s expiry/deactivation leaves the graph node and edge intact. Asset access remains denied unless a separately approved durable graph grant exists. External URL rendering escapes text and performs no server-side fetch.

## Production gates

Production provider tags require the separate DNS/TLS tracking origin, verified cookie/origin isolation, valid test provider IDs, and observed test events after consent. Production graph exposure requires visibility/grant rechecks, moderation controls, and tests against real local D1 authorization state. These gates do not block local development of the bounded contracts using synthetic data.
