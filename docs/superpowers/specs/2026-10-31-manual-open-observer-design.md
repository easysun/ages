# Manual Timeline-open completion observer design

**Scope:** design only. This adds no product instrumentation, dependencies, or edits to the existing Playwright pilot or formal matrix.

## Intent and boundary

Provide a small passive DevTools-console observer for one real Samsung Galaxy S25 Chrome tap on the existing synthetic Timelines list. It emits fixed trace markers from the trusted primary click through the first stable, complete story projection. Its passive instrumentation adds overhead; its two-frame endpoint is an observation upper bound, not an exact render or presentation timestamp. It is diagnostic completion evidence, not an input-to-next-paint, INP, composited-frame, or formal performance result.

The source path supports this endpoint: a list link navigates to a fresh route-keyed editor; the editor publishes its story positions only after all chronological pages pass timeline/version/total checks and the accumulated count/unique-ID checks; the initial fit covers those positions; the SVG exposes first/last ordinal and moment count per group. The first 100 editable details are fetched separately, so they are outside “projection ready.” See `src/client/timelines.tsx:90-125, 723-857, 1913-1968` and `src/client/story-viewport.tsx:574-603`.

## Minimal interface

Run in the already-open Chrome tab, on the same synthetic list document and after the original trace capture has started; the caller is responsible for verified trace start. The helper cannot attest capture status itself. In Elements, select the exact Timeline `<a>` node; the helper accepts that node only (for example, DevTools’ `$0`) and does not search for or fall back to another link.

```js
const openCheck = createTimelineOpenObserver({
  target: $0,
  expectedPath: "<private expected synthetic route path>",
  expectedItems: 100, // exactly 100 or 10000
  timeoutMs: 120000,
});
openCheck.arm();
```

The returned handle has only `arm()`, `status()`, `cancel()`, and idempotent `dispose()`. `arm()` first checks that the retained target is a connected `a.timeline-tile` inside `main#main.timeline-page .timeline-list` in the current document, that the current list document is visible, and that the workload is exactly 100 or 10,000. The expected path is supplied privately by the capture operator and used only for equality checks; the helper never reads the anchor’s `href` or title. It retains the target reference only for event identity, clears it after the activation is bound, and never places route data in markers or status output. The caller-provided path is private configuration, not an independently authenticated route binding; `$0` selection attests the intended anchor, while exact node identity proves which anchor was clicked. Later formal attribution remains separate.

The observer is capture-phase and passive. It never prevents default, stops propagation, patches history/fetch, or alters DOM. It accepts exactly one trusted primary `click` on the bound anchor with no modifiers; use event composedPath for descendant clicks. A synthetic or modified/non-primary click, activation of another anchor, or an extra click before the endpoint invalidates the capture. Record observed pointer modality only when available; do not require pointerdown or pointerup as a new gate for this completion marker. Formal input qualification retains its separate trusted-input and modality checks. The app’s normal navigation handler must still run.

## Completion rule and bounded lifecycle

After the accepted click, observe relevant DOM changes with a bounded MutationObserver and check the current `location.pathname` on each scheduled readiness evaluation. SPA pushState can precede its React DOM mutations: do not rely on popstate alone. Schedule two animation frames for every candidate DOM state and revalidate both frames; coalesce mutation bursts and never run an unbounded permanent frame loop. Require the same document/time origin, exact private expected path, visible page, connected and visible `section.story-viewport[data-viewport="story"]` containing exactly one visible `svg[role="img"][aria-label="Narrative order overview"]` with nonzero bounds. Within `main#main.timeline-page`, a direct child `p[role="alert"].error` after activation invalidates the result; no error text is read or returned. No summary and no viewport means loading, not completion. Later editable-detail loading is outside this endpoint; do not require the `<ol>`.

For the SVG groups, parse only `data-first-ordinal`, `data-last-ordinal`, and `data-moment-count`. Require positive integer counts; each range length must equal its count; sorted ranges must be contiguous and non-overlapping from 1 through the configured expected count; their sum and final ordinal must equal exactly 100 or 10,000. Require the same valid group signature on two consecutive animation frames after the route and projection first pass. Recheck document, route, visibility, and groups on both frames. Any intervening mismatch restarts the two-frame stability check. This is a rendered-DOM/layout check only; it does not establish that Chrome composited or presented either frame.

Emit only `console.timeStamp` labels `ages-open-v1:<workload>:capture-start`, `ages-open-v1:<workload>:primary-click`, and `ages-open-v1:<workload>:completion-end`, where workload is exactly `100-interactive` for 100 or `10000-chronological` for 10000. The capture-start marker records the helper call after the operator has confirmed trace start, not an independently verified trace status. Marker flags mean the calls returned without throwing; trace presence must be checked later. Emit `capture-start` only after the trace is armed and the observer preflight passes. `status()` returns a small allowlisted object: schema version, workload, state (`armed`, `projection-ready`, `invalid`, `cancelled`, `timed-out`), fixed reason code, click count, expected/rendered counts, range-valid flag, same-document/path/visible flags, stable-frame count, and marker-seen flags. No title, URL, `href`, IDs, captions, media text, cookies, event payloads, screenshots, or DOM snapshots are returned or persisted.

The one 120000 ms timeout starts at arm(); before the click the list is allowed until timeout, after click the initial list pathname is allowed until expectedPath or timeout, and any other path invalidates. Visibility loss and projection error produce terminal state `invalid` with respectively `VISIBILITY_CHANGED` and `PROJECTION_ERROR`; explicit cancel/dispose produces `cancelled` with `CANCELLED`; expiry produces `timed-out` with `TIMEOUT`. Other fixed invalid reasons are `WRONG_TARGET`, `UNTRUSTED_INPUT`, `MODIFIED_INPUT`, `EXTRA_CLICK`, `WRONG_ROUTE`, `DOCUMENT_CHANGED`, `OBSERVER_ERROR`. `status()` returns only the chosen fixed reason or null. Use one timeout, at most one pending two-frame verification chain, a fixed number of capture listeners, and no event history buffer. MutationObserver must observe only the minimum subtree and attributes needed for the state; observers never serialize page content. Watch subtree child-list changes and the exact `data-first-ordinal`, `data-last-ordinal`, `data-moment-count`, `hidden`, `style`, and `class` attributes on the stable `#root` ancestor that owns `main`; validate that it exists at arm time and remains connected. Also listen for resize. Evaluate immediately after click, on each coalesced relevant mutation, on resize, and on each frame of the two-frame verification chain. No polling timer or perpetual RAF loop is allowed; timeout is the only timer. `cancel()`, `dispose()`, timeout, visibility loss, a second activation, or a projection error removes listeners and stops all pending work. After the accepted click, permit the original list route until navigation or the single timeout; an observed wrong destination or replacement is invalid. The passive helper does not observe an unreported pathname excursion that leaves and returns between checks; its claim is limited to path equality at each observed check. Continuous route history, if needed, is separate external trace evidence. If replacement is detected while the helper still runs, return `DOCUMENT_CHANGED`; a replacement that destroys the execution context cannot return a status, and external validation treats missing final status or marker as invalid, with no reinjection or resumed session. If no valid endpoint arrives before the fixed timeout, emit no `completion-end`.

## Evidence and gates

The observer establishes that an exact trusted click on the selected anchor in this document was followed by the complete source-controlled story DOM. It does not establish that a trusted click came from a physical touch; modality is separate evidence. It cannot itself see accepted response versions or prove pagination. Keep the version-pinning claim conditional on separately captured, sanitized network/source evidence showing that every continuation used the first accepted version. Likewise, completion markers do not prove unique raw-trace input attribution or trace integrity; a missing/ambiguous input, capture loss, or missing `capture-start` keeps the result invalid/unknown.

Before any physical batch, summarize to the user: **item/workload and action; phone model/build; Chrome version; exact synthetic test URL; one-tap human action sequence; USB/DevTools and port-forwarding state; estimated duration; and the precise unplug point**. Keep credentials out of the URL and keep the observer’s output free of the URL and identifiers.

Pass/fail gates for a later implementation are: (1) pure group-check tests pass for both exact sizes and reject gaps, overlap, duplicates, zero/incorrect counts, and wrong endpoints; (2) browser tests reject synthetic/untrusted, wrong-target, modified/non-primary, duplicate, wrong-route, hidden, replaced-document, partial/stale/error, and timed-out cases while confirming the application click handler still navigates; (3) tests cover `pushState` without `popstate`, DOM commits between RAFs, two-frame revalidation, cancellation, and listener/RAF cleanup; and (4) a supervised S25 run yields one exact-target trusted physical click and one complete endpoint per declared case. Synthetic browser tests validate the helper only, never physical qualification.

## Approaches and remaining limits

Use this standalone DevTools helper. Product-side marker instrumentation would alter the measured app; expanding Playwright would still not observe the manual S25 interaction. Neither is warranted for this observer. The existing `scripts/browser-stimulus-observer.mjs` records trusted stimulus evidence but has no route/projection completion contract; the Playwright pilot’s `completion-end` is emitted by its automation harness and is not evidence from manual Chrome.

The original formal matrix remains unchanged. The Chrome 156 tag audit at `1d17a2e2ee147bb7d6ae2ab6abdb3a2510c17775` is source-only; runtime revision and real-capture loss/input attribution remain pending. No physical measurements or tests were run for this draft.
